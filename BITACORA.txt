1. COMO USAR ESTE DOCUMENTO (retomar contexto desde cualquier punto)
================================================================================

1.1 Proposito
-------------
Este archivo es la bitacora fundamental del proyecto Auralis. Reune, en un solo
lugar y en texto plano, TODO el contexto necesario para que una persona o un
agente de IA puedan retomar el trabajo desde cualquier punto sin depender de
memoria externa ni de transcripciones de chat.

1.2 Que contiene
----------------
  - El estado real del proyecto (fuente de verdad: ver docs/PROJECT_STATUS.md).
  - El historial cronologico de las sesiones de trabajo (que se pidio, que se
    hizo, en que commits, con que verificacion).
  - El catalogo completo de funcionalidades implementadas.
  - La arquitectura, el modelo de datos y el sistema de diseno.
  - Las decisiones tecnicas (ADR) y sus reversiones.
  - Bugs conocidos/parciales/resueltos.
  - El estado de tests y CI/CD.
  - El estado del sitio web y la publicacion.
  - El flujo de trabajo y las convenciones del repositorio.
  - Los pendientes y el roadmap.

1.3 Jerarquia de fuentes de verdad (que gana ante discrepancias)
----------------------------------------------------------------
  1) El CODIGO en el repositorio (siempre la verdad ultima).
  2) docs/PROJECT_STATUS.md  -> fuente principal del estado.
  3) CHANGELOG.md            -> cambios entregados/en desarrollo confirmado.
  4) docs/DECISIONS.md       -> razonamiento de las decisiones (ADR).
  5) docs/FEATURES.md        -> catalogo por funcionalidad.
  6) docs/ARCHITECTURE.md    -> arquitectura.
  7) docs/DESIGN_SYSTEM.md   -> tokens y componentes.
  8) README.md               -> presentacion/stack.
  9) Esta BITACORA.txt       -> sintesis y contexto narrativo.
  Regla: si hay discrepancia, PROJECT_STATUS.md gana sobre los demas docs, y el
  codigo gana sobre todo.

1.4 Como retomar el trabajo (checklist rapido)
----------------------------------------------
  1) Leer "2. FICHA DEL PROYECTO" y "SECCION 3" (ultima sesion) de este archivo.
  2) Correr `git status` y `git log --oneline -10` para ver el estado real.
  3) Correr `./gradlew testDebugUnitTest lintDebug assembleDebug` (ver seccion 12).
  4) Revisar docs/PROJECT_STATUS.md para el estado mas reciente.
  5) Revisar la seccion 14 (PENDIENTES) para saber que sigue.
  6) Antes de tocar UI, leer la seccion 7 (Sistema de Diseno) y los guardrails
     de AGENTS.md.

1.5 Convenciones de este documento
----------------------------------
  - Idioma: espanol. Formato: texto plano ASCII/UTF-8, sin Markdown.
  - Fechas: AAAA-MM-DD.
  - Commits: se referencian por su hash corto (7 caracteres).

2.1 Identidad
-------------
  Nombre comercial : Auralis
  Descripcion      : Reproductor de musica local para Android; minimalista, sin
                     anuncios, 100% offline (privacidad por diseno).
  Paquete          : com.auralis.player
  Empresa          : EstalingradoCorp
  Email de soporte : soporte@estalingradocorp.com
  Licencia         : PolyForm Noncommercial 1.0.0 (Copyright 2025-2026

2.2 Stack tecnologico (segun README.md)
----------------------------------------
  Lenguaje        : Kotlin 2.3.21
  UI              : Jetpack Compose + Material 3 (BOM 2026.08.00)
  Navegacion      : Navigation Compose 2.9.8
  DI              : Hilt 2.60.1
  Base de datos   : Room 2.8.4 (con KSP)
  Reproduccion    : Media3 / ExoPlayer 1.11.0
  Background Work : WorkManager + Hilt 2.11.2
  Async           : Coroutines + Flow 1.11.0
  Testing         : JUnit, Robolectric, Coroutines Test, AndroidX Test (instrumentados)
  Build           : Gradle KTS (Kotlin DSL), AGP 9.3.2
  JDK             : 21 (local y CI)

2.3 Versionado / SDK
--------------------
  versionName : "0.2.0"
  versionCode : 2
  compileSdk  : 37
  minSdk      : 26 (Android 8.0)
  targetSdk   : 36
  Ultima release : v0.2.0 (commit 8304e58 + tag anotado v0.2.0)
  Versionado  : Semantic Versioning (ver CHANGELOG.md). Ej: 1.2.3 -> code 10203.

2.4 Permisos declarados (AndroidManifest.xml)
---------------------------------------------
  READ_MEDIA_AUDIO                 (Android 13+; leer audio)
  READ_EXTERNAL_STORAGE            (maxSdkVersion 32; leer almacenamiento)
  POST_NOTIFICATIONS               (Android 13+; controles en notificacion)
  FOREGROUND_SERVICE               (servicio en primer plano)
  FOREGROUND_SERVICE_MEDIA_PLAYBACK (reproduccion en foreground)
  WAKE_LOCK                        (seguir reproduciendo con pantalla apagada)
  MODIFY_AUDIO_SETTINGS            (efectos AudioFX / ecualizador)
  NOTA: NO se declara RECORD_AUDIO (el aura es reactiva SIN permisos; ver ADR 019).

2.5 Entry points y build
------------------------
  App.kt (Application, @HiltAndroidApp) y MainActivity.kt (Compose, permisos
  runtime). Variants: debug (sin ofuscacion) y release (ProGuard/R8 +
  shrinkResources). Firma de release via local.properties (storeFile, etc.).

2.6 Estado de sincronizacion (al escribir esta bitacora)
--------------------------------------------------------
  main == origin/main (sincronizado). Working tree limpio antes de agregar este
  archivo. Ultimo commit de la serie: merge 929ef6e (2026-10-15).

5. ARQUITECTURA
================================================================================

5.1 Capas (Clean Architecture + MVVM + Jetpack Compose)
-------------------------------------------------------
  1) domain/   : modelos de negocio + interfaces de repositorio. SIN dependencias
                 de Android (solo Coroutines/Flow). Ej: Song, Album, Artist,
                 Playlist, PlaylistSummary, QueueItem, PlaybackState, RepeatMode.
                 Interfaces: LibraryRepository, LibraryFolderRepository,
                 PlaybackRepository, PlaylistRepository, FavoritesRepository,
                 ArtworkColorRepository.
  2) data/     : implementaciones. Room (FavoritesDao, PlaylistDao, LibraryDao),
                 MediaStore (MediaStoreSource, AudioPathFilter), Media3
                 (Media3PlaybackRepository), metadata, scanner (Default/
                 LibraryScanner, Worker, Scheduler, Monitor), repositorios
                 concretos, preferencias (EqualizerPreferences, ThemeController,
                 MusicFolderPreferences).
  3) feature/  : UI por pantalla (Compose + ViewModel con StateFlow).
                 Navegacion: ReproductorNavHost.
  4) core/     : transversal. common/ (audio PlaybackRhythm, color DominantColor,
                 dispatchers, folder SelectedFolders, format FolderLabel/
                 TimeFormat, library MostPlayedSongs, result AppResult) y
                 ui/theme + ui/components.

5.2 Inyeccion de dependencias (Hilt)
------------------------------------
  di/AppModule, di/DatabaseModule (DAOs + Room), di/RepositoryModule (bindea
  interfaces de dominio -> implementaciones), DispatcherModule (IO/Default/Main).

5.3 Hilos y concurrencia
------------------------
  Dispatchers.Default : trabajo intensivo de CPU (UUIDs en HomeViewModel,
                        color dominante, mapping Room->Dominio de
                        RoomLibraryRepository.observe*(), derivados de Inicio
                        folders/popularSongs).
  Dispatchers.IO      : lectura de DB y sistema de archivos.
  Dispatchers.Main    : UI y llamadas obligatorias de Media3.

5.4 Flujo de Inicio (patron anti-jank, ADR 022)
-----------------------------------------------
  - songsFlow / selectedFoldersFlow: observeSongs()/observeSelectedFolders()
    con distinctUntilChanged() + flowOn(Default) +
    shareIn(WhileSubscribed(5 s), replay = 1)  (una sola suscripcion a Room).
  - libraryDerivedFlow: combine(songs, folders) -> LibraryDerived(folders,
    popularSongs). Se recalcula SOLO cuando cambia el catalogo.
  - catalogFlow: canciones + carpetas + estado de escaneo + playlists.
  - combine final (coreFlow + busqueda + favoritos): solo ENSAMBLA referencias
    ya calculadas -> un tick de 500 ms es O(1).
  - RoomLibraryRepository.observeSongs() aplica .flowOn(Dispatchers.Default).

5.5 Seleccion de carpetas y escaneo
-----------------------------------
  - El usuario elige carpetas con SAF (ActivityResultContracts.OpenDocumentTree)
    desde Canciones o desde el estado vacio de Inicio; Ajustes ofrece lo mismo.
  - Cada carpeta se persiste como tree URI en MusicFolderPreferences
    (SharedPreferences "auralis_library_prefs") via LibraryFolderRepository
    (addFolder/removeFolder). UI: MusicFoldersSheet +
    folderDisplayName() (FolderLabel).
  - La app SIEMPRE arranca en Routes.HOME (sin onboarding).
  - MediaStoreSource.getAudioFiles(folderTreeUris) indexa SOLO el audio dentro de
    las carpetas elegidas: de cada tree URI (DocumentsContract.getTreeDocumentId)
    deriva (volumen, ruta relativa) y comprueba pertenencia por VOLUME_NAME +
    RELATIVE_PATH (API 29+; volumen SAF primary -> external_primary) o por
    prefijo de DATA (API < 29). matchedSelectedFolder devuelve la carpeta MAS
    ESPECIFICA que contiene el archivo (o descarta la fila); esa carpeta se
    persiste en sourceFolderUri. AudioPathFilter sigue descartando audio no-musica.
  - DefaultLibraryScanner.sync() lee las carpetas de MusicFolderPreferences y
    escanea; sin carpetas, la biblioteca queda vacia (Inicio muestra estado
    "Anadir carpeta").
  - Al re-escanear, las canciones que ya no aparecen se marcan isAvailable = 0
    (borrado logico), preservando playlists y favoritos.
  - BLINDAJE: si el descubrimiento vuelve VACIO, el scanner NO marca nada como no
    disponible (evita vaciar la biblioteca por MediaStore aun no listo, volumen
    desmontado, SAF sin resolver o sin carpetas).

5.6 Biblioteca: ocultar canciones y resumen de playlists
--------------------------------------------------------
  - Ocultar (reversible) - Room v5: SongEntity.isHidden (DEFAULT 0). LibraryDao
    filtra isHidden = 0 en canciones, albumes, artistas, busqueda y canciones de
    playlist; FavoritesDao tambien excluye ocultas. El scanner PRESERVA isHidden
    en el upsert. Restauracion: observeHiddenSongs/getHiddenSongs/setHidden.
  - PlaylistSummary - PlaylistDao.observePlaylistSummaries() devuelve
    PlaylistSummaryRow (proyeccion con subconsultas COUNT, COALESCE(SUM(
    durationMs),0) y primera coverUri por position, excluyendo isHidden = 0).

5.7 Catalogo por carpetas (ADR 020)
-----------------------------------
  - El catalogo son EXCLUSIVAMENTE las canciones dentro de las carpetas
    elegidas. Persistencia: Room v6 SongEntity.sourceFolderUri (indice
    index_songs_sourceFolderUri). Helpers puros:
    core/common/folder/SelectedFolders.kt (songsInSelectedFolder, libraryFolders)
    y core/common/library/MostPlayedSongs.kt (mostPlayedSongs).
  - UI: fila persistente de carpetas en Inicio -> "Todas"; sin carpeta
    seleccionada no se listan canciones (pista breve); cola acotada a la carpeta
    (onSongClick(song, scope) / playAll(scope)).

5.8 Flujo de audio y efectos
----------------------------
  - Reproduccion estandar Media3 (ExoPlayer), sin efectos extra por defecto.
  - Amplitud para el aura (SIN permisos): PlaybackService construye ExoPlayer
    con AuraRenderersFactory (DefaultRenderersFactory propio) que inyecta
    RhythmAudioProcessor en el DefaultAudioSink. El procesador es passthrough:
    analiza PCM de 16 bits, separa graves (paso bajo ~150 Hz) y agudos (resta),
    sigue envolvente de pico por banda y detecta ataques contra una media
    adaptativa; publica en PlaybackRhythm (core/common/audio) un nivel con un
    "pulso" de caida adaptada al tempo. PlaybackEnergy lo mezcla con su pulso
    sintetico; sin senal fresca (500 ms) usa solo el sintetico. NO se usa
    Visualizer ni RECORD_AUDIO.
  - Ecualizador (AudioFX): PlaybackService detecta audioSessionId dinamico y al
    cambiar de sesion libera el Equalizer previo y crea uno nuevo. Cada banda se
    mapea de dB a milibel con bandLevelRange. IMPORTANTE: instanciar
    android.media.audiofx.Equalizer SIEMPRE dentro de try-catch (dispositivos
    sin soporte de hardware).

5.9 Distribucion de paquetes
----------------------------
  core/ (transversal + diseno) | data/ (persistencia, MediaStore, Media3,
  repos) | domain/ (modelos + interfaces, sin Android) | feature/<pantalla>/ |
  di/ (modulos Hilt). Total: ~139 archivos .kt (main + test + androidTest).

12. FLUJO DE TRABAJO
================================================================================

12.1 Comandos habituales (Windows / PowerShell)
-----------------------------------------------
  Build debug    : .\gradlew.bat assembleDebug
  Tests          : .\gradlew.bat testDebugUnitTest
  Lint           : .\gradlew.bat lintDebug
  Release        : .\gradlew.bat assembleRelease  (o bundleRelease)
  Instalar       : .\gradlew.bat installDebug (con dispositivo conectado)
  ADB (ruta)     : %LOCALAPPDATA%\Android\Sdk\platform-tools\adb.exe
  Nota: el dispositivo fisico usado en desarrollo aparece como "unauthorized"
  hasta aceptar "Permitir depuracion USB".

12.2 Convenciones de git
------------------------
  Commits: Conventional Commits (feat, fix, refactor, style, docs, test, chore).
  Ramas: feature/<nombre>. La rama principal es main; se evita force-push.
  Antes de commitear: inspeccionar git status, git diff y git log --oneline -10.
  No commitear secretos ni archivos de firma (local.properties esta ignorado).
  Cuando origin tiene commits nuevos: fetch + merge (no rebase/force) y resolver
  conflictos preservando ambos lados.

12.3 Proceso de release (docs/RELEASE_PLAN.md)
----------------------------------------------
  1) Working tree limpio. 2) Incrementar versionCode/versionName en
  app/build.gradle.kts. 3) Mover [Unreleased] a la version fechada en
  CHANGELOG.md. 4) ./gradlew bundleRelease. 5) Push a main + tag vX.Y.Z.
  6) GitHub Actions genera el release. 7) Actualizar PROJECT_STATUS.md y
  RELEASE_PLAN.md.

12.4 Documentacion continua (AGENTS.md)
---------------------------------------
  Regla: la documentacion debe reflejar SIEMPRE el estado real del codigo.
  Actualizar tras cada funcionalidad/fix/cambio relevante:
    README.md            <- stack, variants, permisos, novedades
    CHANGELOG.md         <- toda funcionalidad/fix visible (Keep a Changelog)
    docs/PROJECT_STATUS.md <- fotografia del estado real (fuente principal)
    docs/FEATURES.md     <- altas/cambios de funcionalidades
    docs/ARCHITECTURE.md <- capas, DI, threading, flujo de audio
    docs/DESIGN_SYSTEM.md<- tokens/paleta/componentes core
    docs/DECISIONS.md    <- ADR relevantes
    docs/RELEASE_PLAN.md <- estado de hitos
    docs/PLAY_STORE_CHECKLIST.md <- requisitos de Store
    docs/PRODUCT.md      <- vision/pilares/publico/roadmap
    BITACORA.txt         <- este documento (sintesis y contexto narrativo)
  Reglas: no inventar contenido; marcar lo no consolidado; no duplicar;
  PROJECT_STATUS.md gana ante discrepancias.

12.5 Guardrails tecnicos (AGENTS.md)
------------------------------------
  - No modificar la configuracion del motor de audio salvo por AudioFX o
    estabilidad.
  - Busquedas en SQLite con LOWER + REPLACE (insensibles a acentos/mayusculas).
  - Operaciones pesadas (mapeos, UUIDs, DB) en Dispatchers.Default/IO; volver al
